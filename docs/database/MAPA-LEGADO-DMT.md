# MAPA-LEGADO-DMT — Diccionario legado → nuevo

- Fecha del inventario: 2026-09-25 (la base `traccar` está en operación; los
  conteos son instantáneas).
- Alcance: objetos de `traccar.public` y `traccar_qa.public` en el contenedor
  `dmj-db` (TimescaleDB sobre PostgreSQL 17.10).
- Reglas de nombres: [ADR-001](../architecture/adr/ADR-001-nomenclatura-dmt.md)
  y [NOMENCLATURA.md](NOMENCLATURA.md).
- Producción: solo lectura. No se ejecutó DDL sobre `traccar` ni
  `traccar_qa`.
- Esquema destino: `database/schema/*.sql` (nomenclatura `dmt_`).

## 1. Comandos de inspección usados

Todos los comandos se ejecutan contra el contenedor `dmj-db` y son de solo
lectura.

```sh
# Conteo de tablas por base
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select count(*) from information_schema.tables where table_schema='public' and table_type='BASE TABLE';"
docker exec dmj-db psql -U traccar -d traccar_qa -tAc \
  "select count(*) from information_schema.tables where table_schema='public' and table_type='BASE TABLE';"

# Listado de tablas
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select table_name from information_schema.tables where table_schema='public' and table_type='BASE TABLE' order by 1;"

# Vistas, secuencias, hypertables
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select table_name from information_schema.views where table_schema='public' order by 1;"
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select c.relname from pg_class c join pg_namespace n on n.oid=c.relnamespace where c.relkind='S' and n.nspname='public' order by 1;"
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select hypertable_schema, hypertable_name from timescaledb_information.hypertables order by 1,2;"
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select hypertable_name, column_name, time_interval from timescaledb_information.dimensions order by 1,2;"

# Columnas reales de las tablas núcleo
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select column_name||'|'||data_type||'|'||is_nullable||'|'||coalesce(column_default,'-') \
   from information_schema.columns where table_schema='public' and table_name='tc_positions' order by ordinal_position;"

# Conteos exactos de todas las tablas (sin estimaciones de pg_stat)
docker exec -i dmj-db psql -U traccar -d traccar -At <<'SQL'
SELECT format('select %L as t, count(*)::text as n from public.%I', relname, relname)
FROM pg_stat_user_tables WHERE schemaname='public' ORDER BY relname \gexec
SQL

# Definición de la vista
docker exec dmj-db psql -U traccar -d traccar -tAc \
  "select pg_get_viewdef('public.v_device_funnel_daily'::regclass, true);"
```

Para `traccar_qa` se repitieron los mismos comandos con `-d traccar_qa`.

### 2.2 Hypertables y dimensiones

| Hypertable | Dimensión por tiempo | Intervalo | Otra dimensión |
|---|---|---|---|
| `tc_actions` | `actiontime` | 7 días | — |
| `tc_events` | `eventtime` | 7 días | `deviceid` (partición por espacio) |
| `tc_positions` | `fixtime` | 7 días | `deviceid` (partición por espacio) |

La base nueva **no usa TimescaleDB**: el plan pide particionado declarativo
nativo por mes (`PARTITION BY RANGE`), por lo que la migración copia datos a
`tracking.dmt_posicion` y `tracking.dmt_evento` sin extensión de series.

## 4. Mapa de objetos legado → nuevo

Criterios:

- `migrar`: se copia a la tabla destino con ids y fechas originales.
- `recuperar_historico`: histórico fragmentado o pre-purga que se restaura en
  la misma tabla destino, con deduplicación y verificación de rangos.
- `evaluar`: la decisión depende de una validación funcional (por ejemplo,
  confirmar si el uso real justifica una tabla propia).
- `no_migrar`: metadatos del motor legado o datos efímeros/calculados sin
  valor en la plataforma nueva.

## 5. Mapeo de columnas núcleo

Convenciones de la migración:

- Las marcas legadas son `timestamp without time zone` y se interpretan como
  **UTC** (el contenedor opera en UTC): `columna AT TIME ZONE 'UTC'` al
  escribir `TIMESTAMPTZ`. El contrato con la App no cambia.
- `speed` de Traccar está en **nudos**: `velocidad_kmh = speed * 1.852`
  (1 nudo = 1.852 km/h). `0` se conserva como `0`; `NULL` se conserva como
  `NULL`.
- Los `attributes` legados son `character varying` con JSON: se convierten a
  `JSONB` con `NULLIF(attributes,'')::jsonb`; la ETL debe tolerar JSON
  inválido (registrar la fila y dejar `{}`).
- `disabled` se invierte a `habilitado` (`habilitado = NOT disabled`).

## 6. Orden de migración sugerido

1. `iam.dmt_usuario` ← `tc_users` (sembrar `id` e `id_legado`; luego
   `setval`), `iam.dmt_clave_firma` ← `tc_keystore` (tratar como secreto).
2. `tracking.dmt_dispositivo` ← `tc_devices` (sembrar `id` e `id_legado`;
   `setval`).
3. Crear particiones faltantes del histórico (`2026_08`) y cargar
   `tc_positions` + `tc_positions_bak_20260903` + `traccar_qa.tc_positions`
   + `traccar_qa.tc_positions_bak_20260903` con deduplicación.
4. `tracking.dmt_evento` ← `tc_events`; `telemetry.dmt_salud_dispositivo` ←
   `tc_device_health`; `telemetry.dmt_bateria` ← atributos de posición.
5. `operations.dmt_asignacion` ← `tc_user_device`;
   `operations.dmt_alerta` ← `tc_recovery_event` (y `tc_mobile_messages` si
   se decide migrar); `audit.dmt_auditoria` ← `tc_actions`.
6. `iam.dmt_token_fcm` ← `tc_fcm_tokens`; `iam.dmt_token_revocado`.
7. Registrar cada fila en `system.dmt_migracion_mapa` y validar conteos
   contra este inventario.

## 7. Dudas abiertas

- `tc_mobile_messages`: ¿la API nueva conserva la cola/lease de mensajería
  móvil o basta el histórico de acks? De la respuesta depende `evaluar` →
  `migrar`/`no_migrar`.
- `tc_groups` (6 filas): ¿la web nueva usa agrupación de dispositivos? Si no,
  `evaluar` → `no_migrar`.
- `tc_user_user` y `tc_drivers` están vacías; se mantienen en `evaluar` por si
  el inventario funcional de la App descubre uso indirecto.
- El histórico de `traccar_qa` y `traccar` comparte ids de posición; falta
  definir la clave de deduplicación final (`(id, devicetime)` propuesta).
- La zona horaria del particionado es UTC; la vista legada agrupaba por
  `America/Bogota`. Definir si los cortes mensuales deben ser locales o UTC
  (se mantuvo UTC por simplicidad y coherencia con el almacenamiento).
